# prompts/handoff.md

<UpstreamBanner kind="translation" />

Ticket（工单）交接约定：需要原 ticket 负责人作出的具体决定，是一个结构化的 attention（待人工决定）请求，不是常规进度。
它可以在工作继续时提出；人的明确暂停指令和已有授权仍然适用。
GitHub 评审的研判和回复保留原 thread（线程）的规则；由某人的消息引出的问题，在那条消息所写的地方提出，其他问题在原 ticket 对话中提出。
单凭常规进度、模型重试和预算错误，不授权发 IM 消息。
模型重试的诊断信息保留在 ticket 卡片的 model_retry 中；不要为了掩盖失败而更换模型或重试策略。
空的 final 会保留一份成功的报告；不要仅为保留报告的摘要而在 final 里重复报告。
